# 1. 概述
## 1.1 系统简介
rustto 是一套分布式服务器数据备份系统，由三个独立子工程组成：部署在目标服务器上的 Rust 客户端、提供业务与调度能力的 Spring Boot 管理端后端、以及供运维使用的 Vue 管理前端。三端之间通过自定义二进制帧协议（Netty TCP）与 RESTful 接口协同，完成节点注册、备份任务下发与执行、备份产物记录、客户端二进制热下发等核心能力。
核心价值：把目标机上的备份能力拆成一个个独立的“工具（Tool）”，由管理端按名调度；新增一种备份只需新增一个工具 crate，客户端 CLI 与常驻 daemon 无需改动即可识别并执行。
## 1.2 三端架构

说明：后端 HTTP（8080）与 Netty TCP（9600）运行在同一个 Spring Boot 进程内的两个监听端口；前端通过 Vite 代理 / Nginx 反向代理把 /api 请求转给后端 8080。
## 1.3 核心链路
- ① 前端登录获取 JWT，调用 RESTful 接口“新建节点”，后端生成并返回一次性节点 Token（UUID）。
- ② Rust 客户端携带节点 Token，通过 Netty 长连接向后端发送 REGISTER 注册，之后周期性心跳保活。
- ③ 前端创建备份任务（指定模块 backup_file / backup_mysql、参数 JSON、cron 表达式），后端到点经 Netty 下发 TASK_COMMAND。
- ④ 客户端按 module 名调度到对应工具本地执行备份，回传 TASK_RESULT，后端落库为备份记录。
- ⑤ 上传新版本 Rust 二进制后，经 Netty BINARY_PUSH 分片下发到目标节点，节点校验 sha256 后落盘。

## 5.5 生产环境注意事项
- 立即修改默认管理员密码：用环境变量 RUSTTO_INIT_ADMIN_PASSWORD 覆盖，或登录后改密。
- 务必用强随机值覆盖 JWT_SECRET（至少 32 字节）。
- 收紧 CORS：默认 allowedOriginPatterns("*") + allowCredentials(true) 全开，生产应限定为前端域名。
- 多实例限制：PermissionCache 与 ConnectionRegistry 为进程内状态，水平扩展需引入 Redis / 粘性路由。
- 数据库迁移只增不删：禁止删除/修改 db/migration 历史文件。
- 各端 .env 为密钥文件，不得提交；客户端 crates/core 不可修改。
# 6. 使用说明
## 6.1 登录
浏览器访问前端地址，默认账号 admin / admin123（首次登录后请立即修改）。登录成功后前端拉取用户信息（角色、权限码）与菜单树，动态注册路由并注入按钮级权限指令 v-permission。admin 角色自动 bypass 所有权限校验。
## 6.2 节点管理
- “新建节点”只需填写节点名；创建成功后弹窗一次性回显 nodeToken（仅展示一次，请妥善保存）。
- 把该 token 写入目标机客户端 .env 的 NODE_TOKEN，启动 daemon 即可注册上线。
- 列表展示节点状态（online/offline）、客户端版本、最近心跳时间；删除节点会同步清理其在线连接。
- 注意：节点 token 目前不支持轮换/重置，遗失只能删除节点重建。
## 6.3 备份任务
“备份管理 / 任务”页可创建/编辑/删除/立即执行备份任务。任务字段：

- “执行”立即下发：节点在线则下发 TASK_COMMAND 并预置一条 pending 记录，离线则提示未下发。
- 客户端执行完成后回传 TASK_RESULT，记录更新为 success/failed 并写入产物路径、大小、sha256、错误信息。
## 6.4 备份记录
“备份管理 / 记录”页可按任务过滤、分页查看历史备份记录，含状态、产物路径、大小、起止时间、错误信息等。
## 6.5 二进制版本管理与热下发
- “备份管理 / 二进制”页选择文件、填写版本号后上传，后端记录 sha256、大小、上传时间。
- “下发”选择目标节点，后端将整包 base64 按 512 KiB 分片，逐帧 BINARY_PUSH 下发。
- 客户端收齐分片后校验 sha256，通过则落盘为 data_dir/rustto-client-<version>.bin，并回传 BinaryAck。
## 6.6 系统管理（RBAC）
系统管理提供完整的基于角色（RBAC）的访问控制，包含以下子模块：

- 权限模型：用户 → 角色 → 菜单/权限点。接口通过 @RequirePermission("code") 声明所需权限码，前端按权限码控制按钮显隐。
- 默认角色：admin（超级管理员，拥有全部菜单与权限）、viewer（只读访客，仅备份只读）。

## 10.3 日志策略
- 客户端：tracing + tracing-appender，按日期滚动，文件名 client.log.YYYY-MM-DD，默认级别 info,rustto=debug（RUST_LOG 可覆盖）。

## 10.4 已知差异与注意事项
- 根 README 仍把客户端目录写作 client/，实际为 processor/；模块 modules 已拆分为 backup-file / backup-mysql / common / tools。
- 前端 README 写“Vite 5”，实际为 Vite 8.1.5。
- 节点 token 校验为明文字符串相等，非哈希比对；DB 中不主动过期，无轮换接口。
- JWT 与节点 Token 是两套独立凭证：前者 HS256、12 小时过期；后者 UUID。
- 鉴权一律以 sys_user_role 为准，登录返回的 legacy role 字段仅作兼容。
- backup-mysql 的 password：旧命令默认空串可用，但 tool run 走 JSON 时该字段不可省略（否则反序列化失败报 Params 错误）。
- 代码中暂未见：登出/刷新 token、节点 token 轮换、HTTPS、Dockerfile、备份产物与二进制的清理任务。
